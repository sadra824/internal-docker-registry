Docker Registry API v2

رجیستری اختصاصی صدهانت — کامل، سریع و همیشه در دسترس

مرجع کامل ایمیج‌های داکر برای زیرساخت شما؛ هر ایمیج از هر رجیستری عمومی، دریافت و با همان پروتکل استاندارد Registry v2 سرو می‌شود — و برای دور زدن تحریم و محدودیت رجیستری‌های خارجی، بدون واسطه و بدون دردسر قابل استفاده است. با فعال‌کردن کش، ایمیج‌های پرکاربرد با تأخیر کم و بدون مصرف دوباره پهنای‌باند در دسترس هستند.

نحوه کار

هر docker pull این مسیر را طی می‌کند. برای دیدن حرکت درخواست، دکمه شبیه‌سازی را بزنید.

  1. ۱

    کلاینت داکر

    docker pull registry.sadhanet.com/library/nginx:latest — رجیستری همان پروتکل استاندارد Registry v2 را صحبت می‌کند؛ پس کلاینت نیازی به تغییر ندارد.

  2. ۲

    بررسی کش

    جست‌وجوی منیفست و blobها در کش (در صورت فعال بودن)، با کلید digestهای sha256 و به‌صورت content-addressed.

کش hit
  1. ۳

    سرو از کش

    منیفست و لایه‌ها مستقیم از کش استریم می‌شوند — بدون ترافیک خارجی، با تأخیر در حد شبکه محلی.

کش miss
  1. ۳

    دریافت از طریق سرویس منبع

    سرویس همه رجیستری‌های پیکربندی‌شده را به‌صورت موازی از طریق dockerimagesave.akiel.dev امتحان می‌کند — اولین جواب برنده است.

  2. ۴

    تبدیل و ذخیره

    tarball مربوط به docker save باز می‌شود، به blobها و منیفست‌های content-addressed تبدیل و در کش نوشته می‌شود.

  3. ۵

    پاسخ به کلاینت

    داکر تصویر را از منیفست و blobها — دقیقاً مثل یک رجیستری معمولی — می‌سازد.

کش به‌طور پیش‌فرض خاموش است؛ در این حالت داده‌های موقت بعد از ۳۰ دقیقه به‌صورت خودکار منقضی می‌شوند و با فعال‌کردن کش، پاک‌سازی دوره‌ای حجم را زیر CACHE_MAX_SIZE نگه می‌دارد.

امکانات

هر چیزی که از یک رجیستری اختصاصی کامل انتظار دارید.

  • سازگار با Registry v2

    بدون هیچ تنظیمی با docker pull، docker build، میرورهای Kubernetes و هر کلاینت OCI کار می‌کند.

  • کش اختیاری

    کش به‌طور پیش‌فرض خاموش است و داده‌های موقت بعد از ۳۰ دقیقه خودکار حذف می‌شوند. با CACHE_ENABLED=true بلاب‌ها و منیفست‌ها به‌صورت دائمی و content-addressed ذخیره می‌شوند.

  • fallback روی چند رجیستری

    ۱۳ منبع بالادستی — docker.io ،ghcr.io ،quay.io ،gcr.io ،mcr.microsoft.com، آروان‌کلود و… — به‌صورت موازی امتحان می‌شوند؛ اولین موفق برنده است.

  • پشتیبانی چندمعماری

    نسخه پلتفرم مناسب میزبان با DEFAULT_PLATFORM_OS/ARCH انتخاب می‌شود (پیش‌فرض linux/amd64).

  • تبدیل در لحظه

    tarballهای docker save و OCI layoutها به‌صورت خودکار باز و به ساختار استاندارد رجیستری باز‌بسته‌بندی می‌شوند.

  • سبک و کم‌نیاز

    با حداقل منابع و بدون وابستگی‌های سنگین اجرا می‌شود؛ راه‌اندازی کامل با یک دستور و بدون تنظیمات پیچیده.

شروع سریع

در کمتر از یک دقیقه بالا می‌آید.

راه‌اندازی (Self-host) 
git clone https://github.com/sadra824/internal-docker-registry.git
cd internal-docker-registry
npm install
npm start             # روی پورت :5000 بالا می‌آید

# دریافت هر ایمیج عمومی از طریق رجیستری:
docker pull localhost:5000/library/nginx:latest
فعال‌کردن کش (اختیاری) 
# کش به‌طور پیش‌فرض خاموش است؛ برای فعال‌سازی، این متغیرها را
# در فایل پیکربندی (wrangler.jsonc ← بخش vars) تنظیم کنید:
CACHE_ENABLED=true
CACHE_MAX_SIZE=10GB   # سقف حجم کش (اختیاری)
استفاده به‌عنوان registry mirror (اختیاری) 
# در /etc/docker/daemon.json — همه pullهای داکر به‌صورت شفاف کش می‌شوند:
{
  "registry-mirrors": ["https://registry.sadhanet.com"]
}

سپس http://localhost:5000 را باز کنید — همین صفحه توسط خودِ سرویس سرو می‌شود.

دستورهای API

سطح الزامی Registry v2 — فقط‌خواندنی (push پاسخ 501 می‌گیرد).

دستور کاربرد
GET /v2/ بررسی نسخه
GET /v2/<name>/manifests/<ref> دریافت منیفست (تگ یا digest)
GET /v2/<name>/blobs/<digest> دریافت blob / لایه
HEAD /v2/<name>/blobs/<digest> بررسی وجود blob
GET /v2/<name>/tags/list فهرست تگ‌های کش‌شده
POST /v2/…/blobs/uploads/ پشتیبانی نمی‌شود — فقط pull
